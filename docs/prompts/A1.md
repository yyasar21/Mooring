# Phase A1 — vault + connection tree + SSH

Goal: a usable SSH connection manager with an encrypted vault. One PR per numbered item.

1. Vault: create / unlock / lock / change password / auto-lock (idle, screen lock, sleep); OS keyring wrap as opt-in "unlock with Touch ID / Windows Hello"; `mooring vault export --age`; test vectors under `crates/mooring-vault/tests/vectors`, verifiable with the `age` CLI. Calibrate Argon2 memory cost to the host (target ≈ 500 ms), store the chosen params in the header.
2. Data model: folders, connections, tags, credentials (password, SSH key + passphrase, certificate), credential inheritance down the tree, per-connection overrides, full-text search. SQLite (rusqlite bundled) with sealed sensitive columns; migrations.
3. SSH session: russh with host-key TOFU + known_hosts compatibility, keyboard-interactive + publickey + agent, port forwarding (L/R/D), SFTP panel (browse, upload/download with progress, drag-drop), terminal via xterm.js + WebGL, streaming over Tauri channels; weak algorithms disabled by default.
4. UI: three-pane layout for real; command palette opens any connection by search; tabs with detach-to-window; inspector shows properties and a read-only credential reference; copy-password command with 30 s clipboard clear and audit entry; dark/light themes; keyboard-first.
5. Audit log viewer screen; syslog mirror option (xlog01).
6. Tests: proptest on vault round-trips and tamper detection; cargo-fuzz targets for vault header parsing and SSH packet handling (1 h nightly); Vitest for stores; Playwright E2E: create vault → add folder → add SSH connection to xinfra01.homelab.xyz → open session → run `uname -a` → lock vault.

Exit criteria: all green on 3 OSes; `docs/security/a1-review.md` sign-off; threat model updated; handoff notes written.

Decision needed: SQLite file name/location; whether the audit log is per-vault or per-app.
