## Done
- **Runtime** (`src/secrets_runtime.rs`): `AppState.secrets: Arc<SecretsRuntime>` holds one
  `SecretsEngine` over one in-memory `TokenCache` (system clock; tests inject `FakeClock`).
  `Ready` carries it too, so graphical reconnects re-resolve. The renewer (15 s tick) starts on
  first use inside a Tokio runtime and from `oidc_window::install` at setup.
  - `vault::lock` → `secrets.on_lock()`: every OIDC flow fails (`locked`) and its window
    closes. AppRole/OIDC tokens are revoked (`revoke-self`, 3 s each, in the background).
    `token`-method tokens are only forgotten.
  - `AppState::shutdown` → `secrets.shutdown()`: the same, waiting up to 4 s.
  - `AuditBridge`: `SecretEvent` → `mooring-audit`. A `tokio::task_local` attaches the
    connection to the `secret_resolved` / `secret_failed` rows of a connect.
- **Resolver** (`commands/connect_plan_external.rs`; `connect_plan::plan` is now `async`).
  Before the plan takes the vault/store locks, the primary credential (and the SSH `become`)
  is checked. If it is `external_ref`:
  1. the source is read (`source.not_found`); `onepassword` / `bitwarden` give
     `credential.kind_unsupported`;
  2. `engine.resolve` runs with no lock held, and the vault is re-checked as unlocked
     (`vault.locked`);
  3. the result is mapped into the `ConnectSecret` of `target_kind` (`user_password`,
     `domain_user`, `ssh_key`, `vnc_*`, `sudo_become` as become) under the same matrix as a
     stored credential.

  `ResolvedSecrets` are dropped (zeroized) as soon as the plan exists. Errors are E1's codes.
  `credential_used` and `secret_resolved { connection, credential, source, reference,
  version, target_kind, fields }` are audited.
- **Audit** (`mooring-audit`, next to the credential events): `secret_login`,
  `secret_resolved`, `secret_failed`, `secret_revoked`, `secret_source_changed { changed[],
  warning }` (warning = `caPem`/`allowHttp`; create lists `created`, delete `deleted`),
  `secret_refused { source?, action, detail }`. A refusal row is written for an OIDC
  navigation (detail = origin only), a delete refused as in use, an OIDC timeout / close /
  lock / state mismatch and a window failure.
- **OIDC window** (`src/oidc_window.rs`):
  - The window is `oidc-<sourceId>`, built like a web window: devtools off, zoom hotkeys off,
    autofill off, `incognito`, the upload-blocking init script, pop-ups `Deny`, downloads
    `false`, permissions `Deny`. Its capability is empty (`capabilities/oidc.json`, also in
    `tauri.conf.json`), and the guard refuses the `oidc-*` label for every command.
  - `on_navigation` → `navigate()`:
    - the IdP origin and `allowedOrigins` load;
    - the fixed redirect URI with the right `state` is refused: the window closes and the code
      is exchanged in the background (`complete_oidc`);
    - a redirect with a foreign `state` or an IdP error ends the flow (`state_mismatch`);
    - anything else is refused and audited.
  - Timeout is 5 min on the cache clock, checked lazily and also by a real-time timer. There is
    one flow per source: `begin` returns the waiting session and focuses its window. Closing
    the window natively → `closed`.
- **Guard / manifest / goldens:** 10 `Scope::Main` rows, `permissions/mooring-main.toml`
  (+ autogenerated toml), `secret_source_oidc_status` added to the passive list, and
  `oidc.json` in the capability snapshot test (`oidc_capability_grants_nothing`).
  `ipc-manifest.json`, `ipc-passive.json` and `ipc-codes.json` were regenerated with
  `MOORING_BLESS=1`.

## IPC for U3 (exact JSON)
```
secret_source_list()        -> SecretSource[]
secret_source_get({ id })   -> SecretSource
secret_source_create({ name, address, namespace?, authMethod: "token"|"approle"|"oidc",
                       authMount?, credentialId?, oidcRole?,
                       options?: { caPem?, allowHttp?, allowedOrigins?[] } }) -> SecretSource
secret_source_update({ id, ...same as create })  -> SecretSource   # cached token forgotten
secret_source_delete({ id })   -> null      # source.in_use while an external_ref names it
secret_source_test({ id })     -> { ok, method, ttlSeconds|null, renewable, policiesCount,
                                    error: code|null, category: string|null }
secret_source_revoke({ id })   -> null      # revoke (AppRole/OIDC) + forget; works locked
credential_external_test({ credentialId })
  -> { ok, version|null, present: string[], missing: string[], extra: string[],
       error: code|null, category: string|null }   # names only; ok = no missing, no extra
secret_source_oidc_begin({ id })        -> { sessionId, windowLabel: "oidc-<id>" }
secret_source_oidc_status({ sessionId }) -> { state: "pending"|"done"|"failed", sourceId,
                                              error: null|"timeout"|"closed"|"locked"|"exit"|
                                              "state_mismatch"|<category> }   # passive

SecretSource = { id, name, kind: "vault", address, namespace|null, authMethod, authMount,
                 credentialId|null, oidcRole|null,
                 options: { caPem|null, allowHttp, allowedOrigins[] }, createdAt, updatedAt }
```

Errors:
- `input.invalid` (field name only, never a value);
- `vault.locked`, `source.not_found`, `source.in_use`, `credential.in_use` (deleting a login
  credential), `credential.incompatible` (wrong login kind), `session.not_found` (unknown
  OIDC session), `window.failed`;
- at connect: `credential.external_unavailable` (message carries the category),
  `credential.external_shape`, `credential.external_not_found`,
  `credential.external_root_token`.

Typical flow: `oidc_begin` → poll `oidc_status` every 1 s until it leaves `pending`, then
`secret_source_test`.

### Differences from the U1 typed IPC (UI follows this list)

| U1 / ADR name | E2 (Rust) |
| --- | --- |
| `secret_source_logout({ id })` | `secret_source_revoke({ id })` |
| `external_ref_test({ credentialId })` | `credential_external_test({ credentialId })`, plus `extra[]` and `category` |
| `secret_source_oidc_start({ id }) -> { windowLabel }` | `secret_source_oidc_begin({ id }) -> { sessionId, windowLabel }` |
| `secret_source_oidc_status({ id })` with `idle\|waiting\|done\|failed\|timeout` | `secret_source_oidc_status({ sessionId })` with `pending\|done\|failed`; timeout is `failed` + `error: "timeout"` |
| `SecretSourceTest.error: string` | `error` is the code, `category` is separate |
| `ExternalRefFields.fieldMap` | `field_map` (snake_case, E1 decision 1) |
| (new) | `secret_source_get({ id })` |

The command names follow the E2 brief. The brief's codes `_denied`, `_missing_field` and
`_root_refused` correspond to E1's `external_unavailable/forbidden`, `external_shape` and
`external_root_token`; E1's codes were kept.

## Left open
- **Trust prompt for sources.** TLS to Vault uses `caPem` or an existing
  `known_vault_certs` pin. An unknown self-signed certificate fails with
  `external_unavailable/tls`, and there is no TOFU prompt command yet (the kube prompt rides on
  a session channel, which sources do not have). Proposal: `secret_source_trust({ id,
  fingerprint })`.
- **Kubernetes / vSphere:** `connect_plan::kube` is still sync and does not resolve
  `external_ref` (`kube_token` / `kubeconfig` targets). Wiring it needs `kube::open` made async.
- **Runtime OIDC interception** on each OS WebView (does `on_navigation` see the
  `localhost:8250` redirect?) is the ADR-0016 §4 E2E gate and can only be verified by QA with a
  real WebView. The decision logic is tested through the same `navigate()` hook.
- `support::vault_gated_codes` (22 commands) does not list the new commands.

## Decision needed
