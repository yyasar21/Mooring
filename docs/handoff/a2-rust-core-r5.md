## Done
- **AppManifest.** `src-tauri/build.rs` calls `tauri_build::try_build` with
  `AppManifest::new().commands(..)`. The command list comes from `src/guard/table.rs`, which is
  shared with the Rust guard through `include!`. Tauri writes `permissions/autogenerated/*.toml`
  (`allow-<cmd>`/`deny-<cmd>`, committed). `permissions/mooring-main.toml` defines the set
  `mooring-main` (every command).
- **Capabilities** (`tauri.conf.json` `security.capabilities = ["main", "detached", "web"]`):
  - `main.json`: `windows: ["main"]`, `["core:default", "mooring-main"]`.
  - `detached.json`: `windows: ["detached-*"]`, exactly `allow-session-attach`,
    `allow-session-send`, `allow-session-close`, `allow-session-frame-ack`,
    `allow-session-screenshot` and `allow-window-attach`. It has no `core:` permission.
  - `web.json`: `windows: ["web-*"]`, `permissions: []`, no `remote`. Tauri 2.12.5 accepts an
    empty set (the build validates and resolves it), so no `core:` minimum is needed.
- **Rust guard** (`guard::with_guard`) replaces `with_activity` around `generate_handler!`.
  Before any command runs, `guard::check(command, label, sessionId)` does three things:
  - `main` may call everything;
  - `detached-<id>` may call only the six `Scope::Session` commands, and only with
    `sessionId == <id>` (read from the JSON args);
  - `web-*`, unknown labels and unlisted commands from non-main windows get `ipc.forbidden`.
  The check runs before the auto-lock hook, so refused calls are not counted as activity.
  `session_open` keeps its own label check.
- **Golden `src-tauri/ipc-manifest.json`**: `{ command: ["main"] | ["main",
  "detached-<sessionId>"] }`. Bless it with `MOORING_BLESS=1 cargo test -p mooring-app golden`,
  the same way as `ipc-codes.json` and `ipc-passive.json`.
- **Web windows** (`web/`, `commands/web.rs`):
  - One `web-<connectionId>` window per connection, built only from the **stored** options
    (`connection_options`, validated again), so the WebView names an id and never a URL.
  - Builder settings: `WebviewUrl::External(url)`, `devtools(false)`,
    `zoom_hotkeys_enabled(false)` and `general_autofill_enabled(false)`.
  - Storage: `incognito(true)` by default. Persistent connections get
    `data_directory($APP_DATA/web/<id>)` (0700) on Windows/Linux and
    `data_store_identifier(uuid bytes)` on macOS ≥ 14. macOS 11–13 falls back to ephemeral:
    the window opens, `persistent: false` is audited and listed, and the fallback is logged.
  - Native callbacks:
    - `on_navigation` → `NavPolicy::decide`;
    - `on_new_window` → `Deny` (an allowed URL is loaded in the same window instead);
    - `on_download` → `false`, audited, and a `download_blocked` event;
    - `on_permission_request` → `Deny`;
    - `on_document_title_changed` → native title `Mooring · <name> · <current origin>`, and
      the sanitised page title as an event;
    - `on_page_load(Finished)` → a `navigated` event.
  - `Destroyed` → the registry entry is removed, `web_closed` is audited and a `closed` event
    is sent, exactly once (it is idempotent with `web_close`).
  - `connection_delete` closes the window and removes the store directory.
- **Navigation guard** (`web/policy.rs`): the URL is parsed by WHATWG `url`, and its tuple
  origin must be exactly the start origin or an `allowedOrigins` entry (both normalised:
  lowercase, punycode, default port dropped). The guard always refuses:
  - the app origin (`tauri://localhost`, `http(s)://tauri.localhost`, the dev URL in dev);
  - any non-http(s) scheme, including `about:` and `blob:`;
  - any URL with userinfo, even towards an allowed origin.
  `blocked` reports `scheme://host[:port]`, or `scheme:` for opaque URLs.
- **Detach** (`route.rs`, `commands/detach.rs`): each session has a `Route`, and the session
  task and frame pump write through it.
  - `session_attach` from a view moves both sinks there. The view that loses the session gets
    `{"kind":"detached"}`, credits reset and the next frame is full.
  - `window_attach`, or the detached window being destroyed, moves the session back to `main`,
    which gets `{"kind":"attached"}`.
  - A failing detached channel also falls back to `main`, and `closed` is always sent to `main`
    too.
  - `session.detached` / `session.attached` are audited.
- **Lock.** `vault::lock` hides every `web-*`/`detached-*` window and a successful unlock shows
  them again (`window_lock`, through `AppState::lock_observer`). `web_focus`, `web_print`,
  `web_open` and `window_detach` need an unlocked vault.
- **Auto-lock focus:** a focused web or detached window counts as the app being in front.
  Without this, working 60 s in a web window would fire `window_hidden`.
- Audit (mooring-audit) has 7 new events, all of them `Notice`: `web_opened {connection, origin,
  persistent}`, `web_closed`, `web_navigation_blocked {connection, origin}`,
  `web_download_blocked {connection, origin}`, `web_data_cleared`, `session_detached
  {connection, session}` and `session_attached {connection, session}`.
- `ipc-codes.json` gains `web.origin_refused`, `web.clear_failed`, `web.store_failed` and
  `window.failed`, and loses `ipc.unknown` (no Rust command emits it any more; the UI's own
  transport fallback in `ipc.ts` is unaffected).

## IPC for the UI (exact JSON)
```
web_open({ connectionId, onEvent: Channel<WebEvent> })   -> { windowLabel: "web-<connectionId>" }
  # main only. Opening again: focuses the window, events move to the NEW channel.
  # errors: input.invalid (id, not a web connection, options without url), tree.not_found,
  #         vault.locked, web.origin_refused (start URL is the app origin),
  #         web.store_failed, window.failed
web_close({ connectionId })        -> null   # session.not_found when not open; sends closed
web_focus({ connectionId })        -> null   # vault.locked while locked (window stays hidden)
web_reload({ connectionId })       -> null
web_print({ connectionId })        -> null   # vault.locked while locked
web_zoom({ connectionId, factor }) -> null   # 0.25..=5.0 else input.invalid "factor"
web_clear_data({ connectionId })   -> null   # works with or without an open window; audited
web_list()                         -> [{ connectionId, windowLabel, origin, title,
                                         persistent, openedAt }]   # passive (ipc-passive.json)
  # persistent = EFFECTIVE storage (false after the macOS 11–13 fallback)
  # origin = current top-level origin (updated on every page load)

WebEvent (onEvent, snake_case):
{"kind":"title","title":"vSphere Client"}            # sanitised, ≤ 256 chars, page-controlled
{"kind":"navigated","origin":"https://vc.example.test"}
{"kind":"blocked","origin":"https://evil.example.test"}   # or "data:", "javascript:", ...
{"kind":"download_blocked","origin":"https://vc.example.test"}
{"kind":"closed"}                                      # last; also after native close

window_detach({ sessionId })  -> { windowLabel: "detached-<sessionId>" }
  # main only; vault.locked; input.invalid (not a UUID); session.not_found;
  # a second call focuses the open window
window_attach({ sessionId })  -> null      # main or the detached window itself; closes it
session_attach({ sessionId, onEvent: Channel, onFrame?: Channel })
                              -> { protocol: "ssh"|"rdp"|"vnc",
                                   state: "connecting"|"connected"|"reconnecting",
                                   size: { width, height } }   # ssh: 0×0 (send your own resize)
  # main or detached-<sessionId>; rdp/vnc: onFrame REQUIRED (input.invalid "onFrame"),
  # ssh: onFrame refused. onEvent is now required (R2's channel-less form is gone).

New session events (onEvent of session_open / session_attach):
{"kind":"detached"}   # this view lost the session to another view; show the placeholder
{"kind":"attached"}   # main only: the session is back (window_attach or the window closed);
                      # call session_attach with fresh channels (a full frame follows anyway)

ipc.forbidden: any command from web-*; anything but the six from detached-*; any of the six
with another sessionId.
```

## Detached route contract (U3)
- **URL:** the bundled UI at `index.html#/detached/<sessionId>` (ADR-0013). This is not the
  `?detached=` form from the R5 brief: the hash route needs no server and survives the dev
  URL. `<sessionId>` is a UUID.
- **On mount:** call `session_attach({ sessionId, onEvent, onFrame? })` once, then draw.
  `onFrame` is required for rdp/vnc and must be absent for ssh. Ack each frame with
  `session_frame_ack`.
- **Available commands:** `session_attach`, `session_send`, `session_close`,
  `session_frame_ack`, `session_screenshot` and `window_attach`, all for **this** sessionId.
  Everything else fails with `ipc.forbidden`:
  - `vault_status`, `app_info` and any other status call (no vault UI in this view);
  - `session_set_view_only` (keep the view-only toggle in main, or ask for a seventh
    permission);
  - `listen()`: there is no `core:event` permission, so no `vault:locked` listener. Rust hides
    the window on lock instead.
  - closing through the window API: use `window_attach` or the native close button.
- **"Bring back" button:** call `window_attach({ sessionId })`. Rust closes the window and
  `main` receives `attached`.
- **Main:**
  - after `windowDetach`, show the placeholder when `detached` arrives (not before);
  - on `attached`, call `session_attach` again;
  - `closed` arrives in both views.
- **Closing the detached window natively** has the same effect as `window_attach`: the session
  stays open.

## Decisions taken
1. **Labels follow the ADR and U1:**
   - `web-<connectionId>`, not `web-<sessionId>` (one window per connection, as `ipc.mock.web.ts`
     and `WebWindowInfo.windowLabel` already assume);
   - `detached-<sessionId>`.
2. **Web events go on the `web_open` channel as `WebEvent`** (the ADR/U1 shape). There is no
   `WireEvent::WebTitle`, because web windows are not sessions.
3. **The best-effort init script ships, as in the ADR.** It blocks file inputs and the
   `show*FilePicker` APIs. The R5 brief said "initialization_script none", but the ADR is the
   spec here and the script carries no IPC. It is a single constant (`web::window::INIT_SCRIPT`)
   if the security reviewer wants it removed.
4. **Credentials in a navigation URL are refused,** even towards an allowed origin.
   **`about:blank` is refused** as a top-level navigation.
5. **`closed` reaches `main` as well while detached,** so the main tab never stays a
   placeholder for a dead session.
6. **`web_reload` and `web_zoom` work while the vault is locked.** The window is hidden, and
   neither call shows it or touches a secret. `web_focus`/`web_print` refuse.
7. **The autogenerated permission files are committed** (Tauri convention). They are
   rewritten on every build and are deterministic.

## Left open
- **No `tauri::test` MockRuntime.** The `test` feature of `tauri` is not enabled, and enabling
  it is a Cargo.toml change for the orchestrator. The builder code (`web/window.rs`,
  `create_detached_window`, the `Destroyed` hooks, hide/show) is therefore exercised only by
  compile and by qa E2E. Everything it calls is unit-tested: policy, plan, registry, route,
  guard, the lock observer.
- **Per-OS permission handling, unverified at runtime:**
  - macOS: WKWebView asks only for media capture, so geolocation and notifications follow
    WebKit defaults (no prompt, because the app has no entitlement). Clipboard read and MIDI
    are not exposed.
  - Linux: the WebKitGTK handler covers all the kinds listed in the ADR.
- **macOS persistent store wipe:** `clear_all_browsing_data` runs only while the window is
  open. A closed macOS window's identifier store cannot be removed (Tauri has no
  `WKWebsiteDataStore.remove(forIdentifier:)`). On Windows/Linux the directory is removed; if
  WebView2 still locks it while the window is open, the error is swallowed after the in-place
  clear.
- **Not built (ADR §Credentials):** mTLS (`x509`), `api_token` headers and the `proxy_url`
  "via SSH" option.
- **The 16-origin limit is enforced only by `WebConnOptions::validate`.** Exceeding it fails
  `web_open` with `input.invalid`.

## UI must match (U3)
- `decodeSessionEvent` must learn `attached`. Today an unknown kind decodes to `closed`, so
  "unrecognised session event" would close the tab. `attached` is only sent after a detach,
  which no UI does yet, so nothing breaks before U3.
- `sessionAttach` must always pass `onEvent`, and pass `onFrame` exactly for rdp/vnc (the mock
  already does this).
- `session_attach` may return `protocol: "ssh"` with size 0×0.
- The detached view must not call anything outside the six commands (see the route contract
  above).
- `web_list` is passive. `POLLED_COMMANDS` may add it if U3 polls it.
