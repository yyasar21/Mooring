# A3 rust-core — S2 vault sync commands, runner and Gate

Branch: worktree of `a3` @ 9c900f5. Spec: ADR-0017 §3–5, owner decisions 10–11, S1 handoff.
Not merged.

## Done
- **Commands** (`src-tauri/src/commands/sync*.rs`, all `Scope::Main`, all `vault.locked` while
  locked): `sync_configure`, `sync_status` (passive), `sync_now`, `sync_resolve_fork`,
  `sync_disable`, `vault_join`. Plain functions take `(&AppState, &SyncHub, prompter,
  autolock)`; the Tauri wrappers pass the native `DialogPrompter`.
- **Runner** (`src-tauri/src/sync_runner.rs`): `SyncHub` (managed state) is single-flight for
  every command and the runner (`sync.in_progress`). The runner ticks every 5 s and starts runs
  only while unlocked. After an unlock the first run comes within 0–30 s, then every
  `intervalMinutes` plus 0–60 s of jitter. A manual-only config or a pending fork or rollback
  alarm schedules nothing. A lock aborts the runner's in-flight task, and a command's run fails
  at its next vault access with `vault.locked`. Background runs never open a dialog: an
  unpinned endpoint shows up as `lastError.code = "http.trust_prompt"`.
- **Credential** `s3_access_key` (amends ADR-0009 as ADR-0017 §4 says). Fields:
  `access_key_id` (required, alphanumeric) and `region?`. Secrets: `secret_access_key`
  (required) and `session_token?`. It has no protocol row, it is not a reference target, and
  nothing about it is copyable. Store migration **0006** rebuilds `credential` to widen the kind
  `CHECK`. The credential is opened from the vault for each run, and its `SecretString`s drop
  (zeroize) once the S3 signer is built.
- **Gate** (`sync_gate.rs`): when `mooring-http` returns `http.trust_prompt` for the endpoint, a
  native dialog offers "Trust and remember", "Trust once" or "Cancel". The first pins through
  `KnownCerts::add_and_save` into `known_sync_certs`, the second sets `trusted_once` for that
  run, and the call is then retried once. The decision is audited as
  `cert_decision { protocol: "sync" }`. Cancel returns `http.trust_prompt`. `sync_resolve_fork`
  asks for a native confirmation ("Discard and resolve"), and cancelling it returns
  `sync.cancelled`. Both dialogs hold the `AutoLock::dialog_guard` exemption.
- **Trust-file coordination**: `mooring_core::known_certs::write_lock(path)` is now public, and
  it is the single per-path lock registry. The TOFU writers, `KnownHosts::add_and_save`
  (proto-ssh now uses the same registry) and the sync apply all use it. The apply holds the lock
  of every trust file for its whole duration. There is no in-memory trust cache to reload: SSH
  and every `mooring-http` client read the file at each connect.
- **Audit**: `sync.configured`, `sync.disabled`, `sync.pushed { counter, bytes }`,
  `sync.pulled`, `sync.merged { counter, conflicts }`,
  `sync.fork_detected { remote, last }`, `sync.rollback_detected { remote, last }`,
  `sync.fork_resolved { keep, counter }` and `sync.joined { vault, counter }`. No secret or
  row content appears in any of them.
- **Event** `sync:status`: the full `SyncStatus` is emitted whenever the computed status
  changes (on run start and end, configure, disable, resolve and join).
- **Engine additions** (`mooring-sync`): `SyncEngine::join`, `S3Config.trusted_once`,
  re-exports of `load_base` and `save_state`, and `AuditSink: Send + Sync`, so a run is a `Send`
  future. Store: `rebind_vault_for_join`.
- Guard rows, `mooring-main.toml`, autogenerated permissions, and the goldens
  (`ipc-manifest.json`, `ipc-passive.json`, `ipc-codes.json`, `kinds.snapshot.json`) were
  regenerated with `MOORING_BLESS=1`.

{ "type": "pushed", "counter": 1 } | { "type": "pulled", "counter": 2 }

                       password: "<master password of the synced vault>",

`Conflict.resolution` is serialised by `mooring_sync::Resolution` (S1). The new codes are
`sync.store_not_empty`, `sync.backend_unsupported` (any `backend.kind` other than `s3`),
`sync.in_progress`, `sync.not_configured` and `sync.cancelled`. The S1 codes are `sync.format`,
`too_large`, `tampered`, `wrong_vault`, `header_mismatch`, `rollback`, `fork`, `conflict`,
`unsupported_backend`, `backend`, `keyring_header`, `invalid`, `store`, `vault` and `io`. The
command also returns `http.*` (list in `commands/sync.rs::SYNC_CODES`), `input.invalid`,
`credential.incompatible`, `vault.locked` and `vault.unlock`.

**Join flow for the UI:** on a fresh device, `vault_create` a bootstrap vault (any password),
`credential_create` the `s3_access_key`, then `vault_join`. The joined vault replaces the
bootstrap header, so the device afterwards unlocks with the synced vault's password. The key is
re-created under the joined vault, or the synced copy with the same `access_key_id` is reused.

## Left open
- **Deviation from the brief**: `vault_join` also takes `vaultId` and `password`. A fresh
  device cannot know the object prefix, which is `<prefix>/<vaultId>/`, and it has no list
  call. The remote header also needs the synced vault's master password.
- **Orchestrator files**: `src-tauri/Cargo.toml` gains the internal path dependencies
  `mooring-sync` and `mooring-http`, and `Cargo.lock` changed accordingly. Migration 0006 may
  collide in number with a concurrent K4 or V2 migration, so renumber on merge.
- **UI (U3)**: `ipc.kinds.ts` must gain `s3_access_key`, because the kinds snapshot test will
  fail until it does. `sync_status` is now passive, `POLLED_COMMANDS` can drop its skip, and
  `PENDING_A3_CODES` can drop the codes listed above. The UI's assumed
  `sync.not_found` / `sync_get` / `sync_set` / `sync_probe` do not exist:
  `sync_configure` probes and stores, and `sync_status.config` replaces `sync_get`.
- **Lost update in the trust files**: a pin written between the snapshot read and the apply
  of the same run is overwritten by the merged file. The window is one run, and the next TOFU
  prompt re-pins.
- The rusty-s3 signer keeps the secret key in a plain `String` for the duration of a run, and
  the copy is not zeroized. No `caPem` option yet: private CAs go through the Gate pin.
- `vault_join` writes the joined header after the rows are applied. If that write fails, the
  store is bound to the joined vault while the bootstrap header remains (a rare I/O failure).
  The fix is a retry of `vault_join`, which is refused as `sync.store_not_empty`, so manual
  cleanup would be needed.
